## Creative calls
- The brief's own storyline was built as given: Claude Code terminal → `/effort` picker → **ultracode** → the spinner spark blows up into a film set → the crew shoots a rooftop stunt → "CUT!" → the set shrinks into an editor where four agent sparks cut, grade, score and title in parallel (the "dynamic workflow") → end card.
- The efficiency message is carried by pictures, not only copy: a status line reads "usage 9% of limit" right after ultracode is selected, and the editor's "Session usage" meter only climbs 9% → 14% while six workflow rows complete.
- The reference videos (`/Users/.../jvnZ3SyyxxajVatp.mp4` and the "second video") live on the user's Mac and were never visible to this session. The look is built from Claude brand colours (cream #F0EEE6, ink #141413, orange #D97757) and flat cartoon spark characters.
- The terminal UI is a stylised Claude Code, and the effort list (low → ultracode) is the concept from the brief, not a screenshot.

## Measured vs looked at
- `hyperframes check`: 0 errors. Frames looked at: 0.5, 2.2, 3.2, 5.0, 6.1, 6.8, 7.2–8.7, 9.6–13.1, 14–19.8, 20.2–24.75.

## Weakest shot / next steps
- The editor scene is dense, and the agent sparks on the timeline are small at phone width.
- With more time: a music bed with its drop on the stunt explosion (t≈10.4), a bigger hero shot of one agent, and a 1080x1350 vertical cut for the X feed.

## Warnings kept on purpose
- Contrast and type-floor warnings on text inside the scaled-down set in the program monitor (clapboard and title text at 58% scale): it is a picture, not reading text.
- `line_unread` on the typed prompt and spinner lines: the viewer reads them as they are typed.
- `composition_file_too_large` on studio.html: the set has to stay in one file so it can shrink into the monitor.
